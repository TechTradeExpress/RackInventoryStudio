## Summary

Implemented auto-generated internal `code` fields for all four entity types
(Location, Rack, Device Model, Device). The `code` field is now generated by
the backend when not supplied, is immutable after creation, and is hidden from
all Add/Edit forms.

Extended identity-field validation: `external_ref` is now a valid device identifier
alongside name, serial_number, and asset_tag. All three identifier fields are
normalized (trimmed + case-insensitive) for uniqueness checks: stored as trimmed
original, compared as lowercase. CSV import applies the same normalization for
in-file duplicate detection and repository conflict detection.

## Risks

- Code generation uses a scan-to-first-available-suffix approach (O(n) per creation).
  Acceptable for current scale; a future index-based counter would be faster.
- Identifier normalization (trim + lowercase) means `SN001` and `sn001` are treated
  as the same serial number. This is intentional but could surprise users who expect
  case-sensitive matching.
- Existing repositories retain their codes unchanged (backward compatible).
