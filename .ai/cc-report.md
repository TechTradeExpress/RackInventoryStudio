# Milestone 8 — Native Repository Picker and Desktop Shell Hardening (+ Fix Pass)

## Summary

Milestone 8 improved the Tauri desktop shell from Milestone 7 with three changes, followed by a fix pass addressing capability permission scope and working tree hygiene.

### Milestone 8 changes
1. **Native folder picker** — added `tauri-plugin-dialog` (Rust + frontend). Browse… button opens OS native folder picker; selected path populates the input. Canceling is silent.
2. **Mutex hardening** — `lock_session()` helper replaces all `state.session.lock().unwrap()` calls. Poisoned mutex returns a user-facing error string instead of panicking.
3. **Bundle identifier fix** — `studio.rackinventory.app` → `com.techtradeexpress.rackinventorystudio`. Resolved Tauri CLI warning about macOS `.app` bundle conflict.

### Fix pass changes
4. **Least-privilege capability** — `dialog:default` replaced with `dialog:allow-open`. Only the `open()` dialog command is needed for folder selection.
5. **gen/schemas removed from git tracking** — four generated schema files untracked via `git rm --cached` and their directory added to `.gitignore`. They are build artifacts regenerated by `tauri-build` on every build.
6. **Stale review context removed** — `.ai/review-context.md` (non-timestamped) deleted; timestamped review contexts (`review-context-YYYYMMDD-HHMM.md`) are now the standard.

No lower-level crates were modified.

| Permission | Status |

Source: `tauri-plugin-dialog-2.7.1/permissions/default.toml` confirms `dialog:default = ["allow-message", "allow-save", "allow-open"]`.

## gen/schemas — final decision

These files (`acl-manifests.json`, `capabilities.json`, `desktop-schema.json`, `linux-schema.json`) are generated by `tauri-build` during every `cargo build` / `tauri build` run. They were tracked in the repo since the initial commit but are build output, not source.

Actions taken:
- `git rm --cached` removed all four files from the git index (staged as `D`)
- `apps/desktop/src-tauri/gen/` added to `.gitignore`
- After the next commit, `git status` will be clean for this directory regardless of builds

Verified: `tauri build --verbose` still succeeds with the files untracked. The build regenerates them on disk; `.gitignore` prevents them from appearing in `git status`.

## .ai/review-context.md

Removed. The project uses timestamped review context files (`review-context-YYYYMMDD-HHMM.md`) generated by `bash scripts/ai/build-review-context.sh`. The non-timestamped file was a stale artifact from Milestone 7.

## Risks

- Tauri commands still hold the state `Mutex` lock for the full duration of `validate` and `save`. For large repositories this may briefly block the UI. Acceptable for this milestone.
- `selectRepositoryFolder()` errors surface in the `handleBrowse()` catch block and are shown in the error area.
- The four `D`-staged files are a staged deletion. They must appear in the commit so git stops tracking them. On all subsequent builds they will be regenerated on disk but ignored.
