# Windows Installer CI

Workflow: `.github/workflows/windows-installer.yml`

## How to trigger manually

1. Go to the GitHub repository → **Actions** tab.
2. Select **Windows Installer** from the left sidebar.
3. Click **Run workflow** → choose branch → **Run workflow**.
4. Wait 15–30 minutes for the build to complete.

## Where to find the artifact

After a successful run, open the workflow run page and scroll to the
**Artifacts** section at the bottom. Download
`rack-inventory-studio-windows-installer.zip` — it contains the installer
files generated by Tauri.

## Expected installer files

Tauri v2 on Windows produces up to two installer formats by default:

| File | Format | Notes |
|---|---|---|
| `*.msi` | MSI (Windows Installer) | Requires WiX Toolset on the build runner |
| `*.exe` | NSIS installer | Self-extracting, no WiX required |

If the `windows-latest` GitHub runner does not have WiX installed, only the
NSIS `.exe` is produced. The upload step uses `if-no-files-found: error` so
the run fails visibly if neither file is generated.

## What to expect on Windows 11 (unsigned installer)

The installer is **not code-signed**. When a user double-clicks the
downloaded `.exe` or `.msi`:

- Windows Defender SmartScreen will show a blue "Windows protected your PC"
  dialog.
- Click **More info** → **Run anyway** to proceed.
- This warning appears because the binary has no trusted publisher
  certificate. It disappears after signing is configured.

## Code signing (deferred)

Signing is not configured in this workflow. To add it later:

1. Obtain an EV or OV code-signing certificate.
2. Store the base64-encoded `.p12`/`.pfx` and its password as GitHub Actions
   repository secrets (e.g. `TAURI_SIGNING_PRIVATE_KEY`,
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`).
3. Add the environment variables to the **Build Tauri Windows installer**
   step in the workflow.
4. Refer to the [Tauri v2 code signing docs](https://v2.tauri.app/distribute/sign/)
   for the exact variable names and `tauri.conf.json` configuration.

No secrets, certificate paths, or placeholders have been added to the
repository at this stage.

## What this workflow does NOT do

- It does **not** create a GitHub Release.
- It does **not** publish to any store or distribution channel.
- It does **not** merge any branch automatically.
- It does **not** push any code.
- Artifacts expire after **30 days** and are not permanently stored.

## Build time estimate

A clean build (cold Rust cache) takes approximately **20–30 minutes**.
With a warm Rust cache (`Swatinem/rust-cache@v2`) subsequent builds take
approximately **5–10 minutes**.
