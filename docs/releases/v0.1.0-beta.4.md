## Summary

`v0.1.0-beta.4` is the successor to `v0.1.0-beta.3`, which was fully
prepared as a release candidate but never tagged or published (see
`docs/releases/v0.1.0-beta.3.md` and `docs/BETA3_ROADMAP.md` for that
decision record). Beta.4 contains the complete `v0.1.0-beta.2..v0.1.0-beta.4`
delta: everything originally scoped for beta.3, plus a Windows application
reliability fix and expanded automated test coverage merged since. Windows
x64, unsigned installer, beta scope — same distribution model as beta.1
and beta.2.

## Git and repository workflow improvements

- **Clone repository** — clone an existing RIS repository from a Git URL
  directly in the app, with the same safety/auth handling as push/pull.
- **Hardened clone transport safety** — unsafe Git transports (`ext::`,
  `fd::`, `file://`, and other unsupported schemes) are rejected before any
  process runs; embedded credentials are redacted from every error path,
  not just the URL itself.
- **Clone no longer freezes the application window** (new since beta.3's
  original scope): cloning now runs on a background thread instead of the
  UI/event-loop thread, so the application stays responsive for the
  duration of a clone. No change to clone behavior, authentication, or the
  resulting repository.

## Windows reliability

The clone UI-thread hang fix above is this release's main Windows-specific
reliability improvement: previously, a slow or large clone could make the
application appear frozen (unresponsive to input) for its duration; it now
remains fully interactive throughout.

Windows Git-over-SSH (push/pull/clone) workflows have also been validated
end-to-end against a real Windows + WSL2 + Docker host as part of the
automated test suite, giving higher confidence in Git/SSH reliability on
Windows generally — this is test infrastructure, not an application change;
see `docs/E2E_WDIO_PLAN.md` (Stage 3F.5) for the full program if useful.

## Security

- **Hardened repository clone flow**: transport-safety validation rejects
  unsafe Git transports before any process is spawned; the clone command
  uses `git clone -- <url>` to prevent option injection from URLs beginning
  with `-`; credentials are redacted from git's own stderr output (not just
  the URL) before any error reaches logs or the UI.
- **Restricted rack export write commands** to `.svg`/`.png` targets only.
- A dependency-advisory review was performed during release preparation.
  A newly reported `rkyv` advisory applies to a crate present in
  `Cargo.lock` through an optional `rust_decimal` feature that is not
  activated in this workspace, so the affected `rkyv` code is not compiled
  into the application.
  Other pre-existing Rust maintenance and unsoundness advisories remain in
  the dependency graph. Their affected API/code-path reachability has not
  been fully established, and no safe in-scope upgrade was identified
  during this release preparation stage.
  Frontend audit findings are confined to development, build, and E2E
  tooling rather than the shipped Tauri application runtime.
  The beta.4 release branch introduces no dependency-version upgrades. See
  PR #172's dependency-audit comment for the full package-by-package
  detail.

## Upgrade / install notes

1. Download the beta.4 Windows installer zip from the GitHub release assets
   once published.
2. Extract the zip and run the installer executable.
3. If Windows SmartScreen appears: click **"More info"** → **"Run anyway"**.
4. Follow the NSIS installer steps. The app installs to
   `C:\Program Files\TechTradeExpress\RackInventoryStudio\` by default.
5. Launch from the Start menu or Desktop shortcut.
6. If upgrading from beta.2 or an earlier build: the installer supports
   reinstall/upgrade over an existing install; no manual data migration is
   required — repository data lives in your chosen repository folders, not
   in the application install directory.

**Requirement:** Git must be installed and on `PATH` for repository Git
operations to function. The app will open and manage local repositories
without Git, but commit/push/pull/clone commands require Git on `PATH`.
