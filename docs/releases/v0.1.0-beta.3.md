## ⚠ Beta notice

This is a **beta release** intended for internal testing and early feedback.

- Not suitable for production use without additional validation.

## What's new since v0.1.0-beta.2

Full detail: `CHANGELOG.md`'s `v0.1.0-beta.3` section. Highlights:

### List views, search, and selection

- **Search, sort, and filter** for Devices and Device Models panels.
- **Searchable select (combobox)** replacing plain dropdowns everywhere a
  device, device model, or rack object is chosen — keyword search, full
  keyboard navigation, ARIA support. Applied to the Add/Edit Device form and
  the placement flow.
- **List scrolling and pagination** repaired across all four main panel
  tables (rows beyond the viewport are reachable again; sticky headers work).

### Inventory workflow

- **Contextual Rack Object form** — creating a rack object inline from the
  placement flow now locks its type correctly.
- **Planning / On-site work mode** toggle — new devices default to
  "planned" or "installed" status depending on the active mode.
- **"Create similar"** action for Devices and Device Models — duplicate an
  existing record's non-unique fields into a new Add form.
- **Auto-fill Device Type** from the selected Device Model in the Add/Edit
  Device form.
- **Device Model CSV import** — a full preview/validate/apply workflow,
  alongside the existing Device CSV import.
- Fixed: the placement inspector's "Edit target model" button now renders
  correctly for rack-object placements (previously never appeared).

### Repository

- **Clone repository** — clone an existing RIS repository from a Git URL
  directly in the app, with the same safety/auth handling as push/pull.
- **Hardened clone transport safety** — unsafe Git transports are rejected
  before any process runs; credentials are redacted from every error path,
  not just the URL itself.

### Rack view export

- **Export rack view as SVG or PNG** directly from the rack detail screen,
  built from real rack/placement data (not a screenshot).
- Export writes are now restricted to `.svg`/`.png` targets only.

### Diagnostics

- **Daily log rotation and 30-day retention** — one log file per calendar
  day, automatic cleanup of files older than 30 days, and richer directory
  health information in Settings.

### Testing and infrastructure (not user-facing, included for completeness)

- A complete desktop end-to-end (WebdriverIO) test program now covers 22
  real-binary test specs across repository lifecycle, inventory CRUD,
  placement, CSV import, destructive-operation guards, and local/remote
  (SSH) Git workflows — 72/84 (86%) of the identified workflow surface.
- CI architecture redesigned: shared composite actions, Rust build caching,
  concurrency control and timeouts across every workflow, and a new manual
  WDIO validation workflow.

## Installation notes

1. Download `rack-inventory-studio-v0.1.0-beta.3-windows-installer.zip` from the
   GitHub release assets.
2. Extract the zip and run `Rack Inventory Studio_0.1.0-beta.3_x64-setup.exe`.
3. If Windows SmartScreen appears: click **"More info"** → **"Run anyway"**.
4. Follow the NSIS installer steps. The app installs to
   `C:\Program Files\TechTradeExpress\RackInventoryStudio\` by default.
5. Launch from the Start menu or Desktop shortcut.

**Requirement:** Git must be installed and on `PATH` for repository Git
operations to function. The app will open and manage local repositories
without Git, but commit/push/pull/clone commands require Git on `PATH`.

## Log file location (Windows)

```
%APPDATA%\com.techtradeexpress.rackinventorystudio\logs\
```

One file per calendar day (`ris-YYYY-MM-DD.log`), auto-cleaned after 30 days.
From inside the app: **Settings → Diagnostics and logs → Open logs folder**.

## Smoke-test checklist

Minimum verification before distributing to beta testers — see the full
checklists in [`BETA_WINDOWS_11_QA_EN.md`](../BETA_WINDOWS_11_QA_EN.md) and
the beta.3-specific [`BETA3_QA_RUNBOOK.md`](../BETA3_QA_RUNBOOK.md):

- [ ] Installer runs; accept SmartScreen warning.
- [ ] App launches without error dialogs or console windows.
- [ ] Create a new repository → Git initialized automatically.
- [ ] Clone an existing repository from a Git URL.
- [ ] Add a location → add a rack → place a device via drag-and-drop.
- [ ] Search/sort/filter the Devices list; use a searchable select.
- [ ] Import a Device CSV and a Device Model CSV.
- [ ] Export the rack view as SVG and as PNG.
- [ ] Toggle Planning/On-site work mode; add a device and confirm the
      default status.
- [ ] Open **Settings → Diagnostics and logs** → confirm daily log filename
      and retention window are shown; "Open logs folder" works.
- [ ] Close the app — no crash.

## Known limitations (beta scope, unchanged since beta.1)

- **Windows x64 only.** Linux packages remain deferred.
- **Unsigned installer.** SmartScreen warning is expected until code signing
  is added in a future stable release.
- **No auto-update.** Re-run the installer to upgrade.
- Repository operations other than fast-forward pull may require CLI Git
  for complex merge/rebase scenarios.
